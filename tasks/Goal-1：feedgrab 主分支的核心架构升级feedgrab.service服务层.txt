/goal 在 feedgrab 主分支体系内完成第一阶段核心架构升级：从 `main` 或经用户确认的干净基线新建 `codex/feedgrab-service-layer` 分支，新增 `feedgrab/service/` 服务层，把当前散落在 CLI、reader、login、storage、doctor、MCP 入口中的核心能力整理成结构化 API，并保持现有终端 CLI 命令的用户可见行为不变，为后续 GUI 客户端和 MCP 共用同一后端能力打基础。
验证：先读取 `AGENTS.md`、`CLAUDE.md`、`README.md`、`README_en.md`、`DEVLOG.md`、`pyproject.toml`、`feedgrab/cli.py`、`feedgrab/reader.py`、`feedgrab/schema.py`、`feedgrab/login.py`、`feedgrab/config.py`、`feedgrab/utils/storage.py`、`feedgrab/utils/media.py`、`feedgrab/utils/dedup.py`、`mcp_server.py` 和 `tests/` 中相关测试，确认现有命令、输出路径、session 路径、MCP 入口和测试约定；实现后运行 `python -m pytest`，如环境缺少 pytest 或可选依赖则记录原始错误并运行可执行的最小替代检查；至少运行 `python -m feedgrab.cli` 或等价 CLI smoke，确认终端入口仍可调用；新增或更新针对 service models、FetchService、CLI 兼容层和 MCP service 调用的最小相关测试；最终报告分支名、改动文件、测试命令、测试结果、未覆盖风险和 CLI 兼容性证据。
约束：不得直接在 `main` 上硬改；不得推送远程、合并分支、发布包或部署；不得引入 GUI 客户端、Electron、PySide6、Tauri、商业授权服务或桌面打包代码；不得改变现有 CLI 命令名称、参数语义、默认输出目录、Markdown 输出格式、front matter、去重索引语义、session 文件格式或平台抓取策略，除非有测试和明确兼容说明；不得把授权判断写入 fetcher；不得把平台 Cookie、API Key、session 内容写入日志或测试夹具。
边界：允许新增 `feedgrab/service/` 及其测试；允许为接入 service 层而小步修改 `feedgrab/cli.py`、`feedgrab/reader.py`、`feedgrab/login.py`、`feedgrab/config.py`、`feedgrab/utils/storage.py`、`feedgrab/utils/media.py`、`feedgrab/utils/dedup.py`、`mcp_server.py` 和 `tests/` 中直接相关文件；允许在必要时更新 `README.md`、`README_en.md`、`DEVLOG.md` 以说明服务层和兼容性；禁止修改无关 fetcher 行为、无关 skills、支付图片、历史调研报告、用户未授权的缓存或输出目录；如发现工作区已有与任务无关的未提交或未跟踪文件，必须保留并绕开，不得回滚或覆盖。
迭代策略：先做发现和设计记录，再实现最小可用 service contract；第一步只定义 `feedgrab/service/models.py` 中的 `FetchRequest`、`FetchResult`、`Artifact`、`ProgressEvent`、`ServiceError`、`DiagnosticResult` 等稳定数据结构；第二步新增 `FetchService.fetch_url()`，内部可暂时复用 `UniversalReader.read()`，但必须返回结构化结果和产物路径；第三步把 `cmd_fetch()` 改为调用 `FetchService`，保持终端输出兼容；第四步再按风险从低到高抽取 `OutputService`、`DoctorService`、`LoginService`、`SettingsService`、`JobService` 的最小骨架或实际接入；第五步修正 `mcp_server.py` 入口漂移，使 MCP 通过 service 层调用 reader 能力；每完成一个聚焦步骤就运行最小相关测试，失败时先读日志和失败栈，不连续重复同一修法超过 2 次，最多做 3 轮聚焦修正后报告剩余风险。
完成条件：`codex/feedgrab-service-layer` 分支存在且改动集中；`feedgrab/service/` 存在并提供可被 CLI、未来 GUI worker 和 MCP 复用的结构化接口；现有核心 CLI 单 URL 抓取入口仍能按原方式调用；MCP 入口不再依赖已漂移的 `UniversalReader(inbox=...)` 形式；相关测试通过或缺失依赖被明确记录；最终说明列出 service API、兼容性策略、测试证据、已知未覆盖平台和下一阶段建议。
暂停条件：需要真实平台账号登录、Cookie、API Key、付费服务、生产数据、远程推送、合并主分支、发布包、破坏性删除、批量文件清理、改变公开 CLI 行为、改变输出文件格式、重写大量 fetcher、引入 GUI 技术栈、需要法律或商业授权判断、或同一阻塞在已有证据下连续 3 次无法推进时暂停并向用户确认。

默认选择理由：这是现有仓库的中等风险架构升级，先在独立分支做服务层并保持 CLI 兼容，能让主分支终端用户继续使用，同时为后续 GUI/MCP 共用能力打基础，风险最低。

/goal Complete the first-stage core architecture upgrade for feedgrab inside the main-branch architecture: create `codex/feedgrab-service-layer` from `main` or another user-approved clean baseline, add a new `feedgrab/service/` service layer, consolidate core capabilities currently spread across CLI, reader, login, storage, doctor, and MCP entry points into structured APIs, and preserve the existing terminal CLI user-visible behavior so future GUI clients and MCP can share the same backend capabilities.
Verification: inspect `AGENTS.md`, `CLAUDE.md`, `README.md`, `README_en.md`, `DEVLOG.md`, `pyproject.toml`, `feedgrab/cli.py`, `feedgrab/reader.py`, `feedgrab/schema.py`, `feedgrab/login.py`, `feedgrab/config.py`, `feedgrab/utils/storage.py`, `feedgrab/utils/media.py`, `feedgrab/utils/dedup.py`, `mcp_server.py`, and relevant tests under `tests/` before implementation; after implementation run `python -m pytest`, or record the raw missing-dependency error and run the smallest executable fallback checks if pytest or optional dependencies are unavailable; run `python -m feedgrab.cli` or an equivalent CLI smoke check to prove the terminal entry point still works; add or update focused tests for service models, FetchService, the CLI compatibility layer, and MCP service usage; report the branch name, changed files, commands run, results, remaining risks, and CLI compatibility evidence.
Constraints: do not modify `main` directly; do not push, merge, release, package, or deploy; do not add GUI client code, Electron, PySide6, Tauri, commercial license services, or desktop packaging code; do not change existing CLI command names, argument semantics, default output directory behavior, Markdown output format, front matter, dedup index semantics, session file format, or platform fetching strategy unless tests and an explicit compatibility note justify the change; do not put license gating inside fetchers; do not log platform cookies, API keys, or session content.
Boundaries: writes are allowed only in `feedgrab/service/`, directly related tests, and the minimum related files needed to connect the service layer, including `feedgrab/cli.py`, `feedgrab/reader.py`, `feedgrab/login.py`, `feedgrab/config.py`, `feedgrab/utils/storage.py`, `feedgrab/utils/media.py`, `feedgrab/utils/dedup.py`, and `mcp_server.py`; documentation updates to `README.md`, `README_en.md`, or `DEVLOG.md` are allowed only when needed to document the service layer and compatibility; do not modify unrelated fetcher behavior, unrelated skills, payment images, historical research reports, or user output/cache directories; preserve unrelated uncommitted or untracked files and work around them instead of reverting or overwriting them.
Iteration policy: perform a discovery and design pass first, then implement the smallest usable service contract; first define stable data structures in `feedgrab/service/models.py`, including `FetchRequest`, `FetchResult`, `Artifact`, `ProgressEvent`, `ServiceError`, and `DiagnosticResult`; next add `FetchService.fetch_url()` that may initially reuse `UniversalReader.read()` while returning structured results and artifact paths; next route `cmd_fetch()` through `FetchService` without changing CLI output behavior; then extract or scaffold `OutputService`, `DoctorService`, `LoginService`, `SettingsService`, and `JobService` in low-risk increments; then fix `mcp_server.py` so it no longer depends on the drifted `UniversalReader(inbox=...)` call shape and uses the service layer instead; run the smallest relevant tests after each focused step, inspect logs and tracebacks before retrying, avoid repeating the same failed fix more than twice, and stop after 3 focused repair rounds with a clear risk report if a blocker remains.
Stop when: the `codex/feedgrab-service-layer` branch exists with concentrated changes; `feedgrab/service/` provides structured interfaces reusable by CLI, future GUI worker, and MCP; the existing core single-URL CLI entry point still works from the terminal; the MCP entry point no longer relies on the drifted `UniversalReader(inbox=...)` form; relevant tests pass or missing optional dependencies are explicitly documented; the final report lists service APIs, compatibility strategy, verification evidence, known uncovered platforms, and next-step recommendations.
Pause if: real platform login, cookies, API keys, paid services, production data, remote push, main-branch merge, package release, destructive deletion, bulk cleanup, public CLI behavior changes, output format changes, broad fetcher rewrites, GUI technology stack introduction, legal or commercial license decisions, or the same blocker appears 3 consecutive times under the available evidence.
